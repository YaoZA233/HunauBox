# Agent 聊天与历史记录

在设置中开启 Agent，并填写兼容 Chat Completions 的服务地址、API Key 和模型名称。
升级沿用现有配置，保存配置和打开历史均不会自动请求模型。

## 使用方法

- 右上角时钟按钮打开聊天记录，支持搜索标题和消息内容、继续聊天、重命名、删除单条或全部会话。
- 新建会话会保留已有聊天。发送的消息和回复自动保存在本机，重新打开页面或重启应用后恢复当前会话。
- 回复中的“思考内容”可展开、折叠和选择复制。仅显示服务商在 `reasoning_content` 或 `reasoning` 字段返回的内容；没有返回时不展示思考面板。
- 回复下方显示模型、输入和输出 Token、服务商提供的缓存和思考 Token，以及整轮请求耗时。
- 消息右上角可复制正文；页面右上角菜单可复制完整 Markdown 对话或通过系统分享导出，包含已返回的思考内容和用量。
- 原有校园工具继续使用：查询按需执行，修改作业和调课仍需界面确认。

## 保存与统计规则

会话记录包含展示消息和完整的工具调用上下文，不包含模型配置或 API Key。Key 仍单独保存在设备安全存储中。
关闭 Agent 或清除模型配置会停止请求，历史可在重新开启后查看；退出校园账号会清除聊天记录。
删除聊天不会撤销已经完成的校园操作。

同一轮中的多次模型请求累计计算用量，包括携带上下文和工具结果的后续请求。
缓存 Token 属于输入用量，思考 Token 属于输出用量，不会重复相加。
服务商没有返回的用量显示“未返回”；部分请求缺少用量时标注统计不完整，不按字符数估算或伪造为零。
耗时包含网络、模型和本地工具执行／用户确认时间。

停止请求、切换聊天或离开页面时取消当前任务。重启后未完成的请求会提示中断，不自动重放校园操作。
读取失败时保留原存储并提供重试；保存失败时提示重试保存。新消息保存成功前不会启动模型调用。
每条消息仍限制 4000 字，每个会话最多 20 个用户回合，到达后可新建会话，旧聊天继续保留。

实现使用当前 Flutter／Dio／Riverpod 架构独立编写，没有复制其 Kotlin 源码或接入默认中转服务。
