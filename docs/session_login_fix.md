# 阳光服务与学工会话修复

本次对照用户提供的 `E:/hunau_FlutterProject/otherlib/ChillEast-main` 本地源码，检查统一认证、阳光服务、请假、问卷和学生公寓的实际调用链。

## 为什么之前仍然掉登录

| 原因 | 修复 |
| --- | --- |
| 旧静默登录只判断 WebView 是否到达融合门户。门户 Cookie 仍有效时，即使 SSO 的 TGC 已过期，也会报告成功。 | 采用 ChillEast 的独立 HTTP CIMS/CAS 登录链，每次取得新的 execution、签名、密码 token 和公钥，完成加密认证并验证服务端身份。 |
| 阳光服务页面没有传入续登回调，旧服务也仅在打开表单时尝试恢复；列表、统计、详情没有恢复流程。 | 默认接入完整 SSO 续登，所有读取均验证真实表单身份；复用有效 TGC，不足时刷新统一认证并重新 OAuth 授权。 |
| 阳光服务 OAuth 返回旧 HTTP 回调；自动重定向容易漏掉中间 Cookie。 | 参照 ChillEast，手动逐跳处理，将已知阳光服务回调升级为 HTTPS，保存每一跳 Cookie。 |
| 当前安装的 dio_cookie_manager 3.4.0 会额外将重定向响应 Cookie 保存到 Location 的域。 | SessionCookieManager 仅将 Cookie 存入实际响应域，不把 SSO Cookie 复制到学工或阳光服务。 |
| 打开网页、刷新作业或 WebVPN 恢复时，会导入其他系统的旧 WebView Cookie；历史版本产生的 Domain/path 阴影可能与新会话同时发送。 | 按当前系统限制同步范围，刷新前清除旧业务 Cookie，新会话回写 WebView；完整 SSO 登录清理重复 TGC，并保留服务端 Cookie 属性。 |
| 学工网页入口仅凭 HTTP 200 判断有效；公寓 WebVPN 准备失败发生在重试范围外。 | 校验真实问卷接口的 aaData；公寓准备阶段也纳入一次完整认证恢复。 |

ChillEast 的关键优势是完整取得新 SSO 会话、准确保存 Cookie 属性和逐跳授权。这不意味着服务端会话永不失效；本项目现在补齐自动恢复，减少用户通过打开官网才能续登的情况。当前参考仓库的阳光服务读取方法也没有全部包含续登，本次同时补齐了这些入口。

## 提交与退出

阳光诉求提交前先验证身份，账号变化则阻止使用旧表单。已发送的写入不自动重试；超时、登录跳转或未知响应提示到列表核对。返回 `2` 是手机号/验证码校验失败，`errer` 是重复诉求，只有 `1` 提示成功。表单读取失败可重试，返回列表后刷新记录。

退出登录先取消并等待正在进行的统一认证发布，再清理 Cookie 和凭据，防止迟到续登重新写回旧账号。
